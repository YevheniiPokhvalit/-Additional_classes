## Частина 1: Спадкування (Inheritance) та функція `super()`

Уявімо розробку гри, де є персонажі різних професій: Воїн, Маг, Лучник. У всіх є спільні властивості (`name`, `health`) та методи (`take_damage()`), але є й відмінності: у Мага з'являється `mana`, а у Воїна — `armor`.

Замість копіювання коду ми виносимо спільну логіку в базовий (батьківський) клас, а специфічні класи робимо дочірніми (класами-нащадками).

Принцип **«is-a»** (є різновидом): якщо можна сказати *«Маг є Персонажем»* або *«Собака є Твариною»* — спадкування доречне.

### Як працює `super().__init__()`:
Дочірній клас має викликати конструктор свого батька, щоб ініціалізувати спільні атрибути, а потім додати власні.

```python
# Базовий клас (Parent / Superclass)
class Character:
    def __init__(self, name, health):
        self.name = name
        self.health = health

    def take_damage(self, amount):
        self.health -= amount
        print(f"{self.name} отримав {amount} шкоди. HP: {self.health}")

# Дочірній клас (Child / Subclass)
class Mage(Character):
    def __init__(self, name, health, mana):
        # super() передає управління конструктору Character
        super().__init__(name, health)
        self.mana = mana  # унікальний атрибут Мага

    def cast_spell(self):
        if self.mana >= 20:
            self.mana -= 20
            print(f"{self.name} чаклує Вогняну Кулю! Мана: {self.mana}")
        else:
            print(f"{self.name}: недостатньо мани!")

# Перевірка:
merlin = Mage("Мерлін", 80, 50)
merlin.take_damage(15)  # метод успадковано від Character
merlin.cast_spell()     # власний метод Mage
```

## Частина 2: Перевизначення методів (Method Overriding)

Нащадок отримує всі методи батька, але за потреби може переписати їхню поведінку під себе.

* Якщо в дочірньому класі створити метод з такою самою назвою, як у батьківському, інтерпретатор викличе версію нащадка.
* Якщо потрібно не замінити, а доповнити дію батька, всередині методу знову викликають `super().назва_методу()`.

```python
class Animal:
    def speak(self):
        print("Тварина видає звук")

class Dog(Animal):
    def speak(self):
        # Повне перевизначення:
        print("Гав-гав!")

class Cat(Animal):
    def speak(self):
        print("Няв-няв!")

Dog().speak()  # Гав-гав!
Cat().speak()  # Няв-няв!
```

## Частина 3: Інкапсуляція та модифікатори доступу (`_` та `__`)

**Інкапсуляція** — це приховування внутрішніх деталей реалізації об'єкта від прямого неконтрольованого втручання ззовні, а також об'єднання даних та методів в одне ціле.

### Навіщо це потрібно?
Якщо баланс банківського рахунку публічний (`acc.balance = -100000`), будь-хто ззовні може випадково встановити туди неприпустиме значення або зламати логіку. Доступ має відбуватися лише через контрольовані методи (сетери/гетери).

У Python немає суворих ключових слів `private` або `protected` як у C++/Java, тому використовують угоди про іменування:

1. **Публічні атрибути (public):**
   * Без підкреслень: `self.name`.
   * Доступні для читання та зміни з будь-якого місця програми.
2. **Захищені атрибути (_protected):**
   * Одне підкреслення на початку: `self._speed`.
   * *Джентльменська угода:* атрибут призначений лише для використання всередині самого класу та його класів-нащадків. Python технічно дозволяє змінити `car._speed = 100`, але розробник усвідомлює, що порушує контракт.
3. **Приватні атрибути (__private):**
   * Два підкреслення на початку: `self.__pin_code`, `self.__balance`.
   * Вмикається механізм *Name Mangling* (спотворення імені). Інтерпретатор перейменовує змінну на `_ClassName__variable`, тому прямий доступ `obj.__balance` викине помилку `AttributeError`.

```python
class SafeAccount:
    def __init__(self, owner, balance):
        self.owner = owner          # public
        self._account_type = "Base" # protected
        self.__balance = balance    # private

    # Гетер (Getter) — контрольоване читання
    def get_balance(self):
        return self.__balance

    # Сетер (Setter) — контрольована зміна з валідацією
    def set_balance(self, new_amount):
        if new_amount >= 0:
            self.__balance = new_amount
        else:
            print("Помилка: баланс не може бути від'ємним!")

acc = SafeAccount("Іван", 1000)
# print(acc.__balance)  # AttributeError: 'SafeAccount' object has no attribute '__balance'
print(acc.get_balance())  # 1000
acc.set_balance(-500)     # Помилка: баланс не може бути від'ємним!
```

### Зведена таблиця рівнів доступу в Python

| Синтаксис | Назва | Де доступний | Мета використання |
| :--- | :--- | :--- | :--- |
| `self.field` | Публічний (Public) | Усюди (всередині й ззовні об'єкта) | Звичайні дані без обмежень |
| `self._field` | Захищені (Protected) | Всередині класу та його нащадків | Внутрішні службові поля (угода розробників) |
| `self.__field` | Приватний (Private) | Тільки всередині поточного класу | Критичні дані, захищені від випадкової зміни |
